每个实验室都有一套"能跑"的脚本。它们在写它们的人手里工作得很好：路径是写死的，输入文件放在某个固定的目录，某个参数在三个月前被手动改过一次。然后那个人毕业了，或者只是换了一台机器，整套东西就变成了一堆需要考古的文本。

我们花了不少时间在这类问题上，最后得到的结论并不性感：**让分析可复跑的，通常不是某个新工具，而是一串无聊的决定。** 这篇笔记是我们现在的做法和仍然做不到的地方。它是一篇经验记录，不是产品介绍；里面提到的工具只是我们碰巧在用的实现。

## 可复现不是"再跑一次能出结果"

先把词拆开。同一个脚本在同一台机器上再跑一次能得到结果，这叫可重复（repeatable），门槛很低，大多数交互式分析都能做到。可复现（reproducible）要求更高：换一个人、换一台机器、隔一年，仍能判断这个结论是从哪份输入、哪版代码、哪组参数、哪次运行里来的。

我们实际追求的是第三层：**决策可追溯**。分析里真正难复现的往往不是命令，而是判断——为什么这个样本被剔除、为什么这个阈值定在 0.8、为什么这个结果重跑了三次最后取了第二次。命令可以复制，判断不能。

这三层对应三种记录方式：脚本、环境、决策日志。多数团队只做了前两层。

## 容器只是地板

容器（container）解决了"用户态环境漂移"这个具体问题：把编译器、库、Python 包和系统工具冻结在一个镜像里。它有用，但被高估了。

首先，容器不冻结内核、驱动和硬件。同一个镜像在两种 CPU、两种 GPU 驱动上可能给出不同的浮点结果或不同的并行行为。对大多数分析这无所谓，但如果你的结论依赖"完全相同的输出文件"，容器给不了这个保证。

其次，镜像标签（tag）会漂移。`latest` 或者一个可变的版本号，今天和明天指向不同的内容。我们要求记录镜像的摘要（digest），并且只按 digest 运行；重建镜像要有固定的时间表，而不是"出问题再说"。

第三，容器不记录"为什么"。它只回答"用了什么环境"，不回答"为什么跑这次分析"。把镜像当成可复现性的全部，是这一类工作里最常见的自我安慰。

还有一个实践细节：不要把大体积数据打进镜像。镜像应该只包含代码与依赖，数据通过内容哈希引用；否则镜像会变成不可维护的归档，每次重建都要重新搬运几百 GB。

## 把配置和参数变成代码

工具自带的默认值是隐形参数。它们随版本变化，而且不会出现在你的命令历史里。我们的规则很简单：**任何影响输出的参数，都必须出现在版本化的配置文件里**，包括看起来无关紧要的那些——随机种子、线程数、排序顺序、locale、临时目录、并行分块大小。

线程数会影响某些工具的输出顺序甚至浮点累加顺序；locale 会影响字符串排序；临时目录会影响失败时的中间文件。这些都不该靠"我记得当时是这样"来保证。

工作流管理器（workflow manager，如 Snakemake、Nextflow）在这里的价值是结构性的：把分析写成有向无环图，每一步声明输入、输出和资源，失败可重入，日志按任务归档。但要说清楚它不做什么：它不会替你记录业务决策，也不会阻止你在规则里写一个隐藏的 `if`。图的形状好，不代表科学判断是对的。

配置本身也要校验。我们倾向给配置写一份模式定义（schema），在运行开始前拒绝未知字段和缺失字段。一个拼错的参数名被静默忽略，比报错难查得多。

## 溯源：记录"做了什么"之外的东西

传统日志记录命令和版本，这已经比没有强。但真正让人在半年后还能接手的，是下面这几项同时存在：

```yaml
# 一次运行的清单（manifest）：输入、环境、命令、输出与判断都在这一个文件里。
run_id: 2026-03-18T09-42-11Z_rnaseq-07
operator: fangchao
reason: "重新运行：上一轮 STAR 索引版本与参考不一致"
inputs:
  - path: data/raw/sample07_R1.fq.gz
    sha256: "9f2c…"
  - path: data/ref/genome.fa
    sha256: "1a7e…"
environment:
  image: "registry.example.org/lab/rnaseq@sha256:4b1d…"
  tool_versions: {star: "2.7.11b", samtools: "1.21"}
command: ["snakemake", "-s", "workflow/Snakefile", "--configfile", "config/sample07.yaml"]
params_sha256: "c03a…"
outputs:
  - path: results/sample07/quant.tsv
    sha256: "77b2…"
status: succeeded
```

配合一个简单的哈希清单，输入和输出就不会在"我记得没改过"的争论里丢失：

```bash
# 为输入生成内容哈希，写进 manifest；输出完成后对输出做同样的事。
find data/raw -type f -name '*.fq.gz' -print0 \
  | sort -z | xargs -0 sha256sum > inputs.sha256

# 所有产物按内容寻址归档：路径可以变，哈希不会。
sha256sum results/sample07/*.tsv >> outputs.sha256
```

两个原则值得强调。第一，**溯源记录是追加的，不覆盖**。重跑产生新记录，旧记录保留；把失败运行和负结果也留下，否则下一个人会重复踩同一个坑。第二，**"做了什么"和"得出了什么"要分开存**。前者是 manifest，后者是分析笔记；混在一起，改结论时就会顺手改历史。

## 执行层：把云平台接进同一个流程

本地跑和远程跑（集群、云主机）如果走两套流程，可复现性会在边界上断掉：本地没有日志，远程没有上下文，"在服务器上能跑"变成口头知识。我们的做法是把执行层收敛成一个接口：同样的命令、同样的日志格式、同样的退出码，不管背后是本机还是远程机器。

我们的一部分分析跑在 DCS Cloud（BGI Research 的组学云计算平台）上：提交容器任务、复用平台上已有的 WDL 流程、查看运行状态与资源消耗。为了让 agent 和人都能安全地使用这一层，实验室内部写了 dcs-harness，一个把 `dcs` 命令行接进 agent 的插件。它做的事情很具体：先建项目、写计划、等人批准，再执行；能检索平台上的公共数据与流程；执行前静态检查脚本里的危险命令与硬编码密钥；除了在线跑容器任务，也能提交离线或并行作业并记录成本与资源；最后把结果整理成一份自包含的 HTML 报告。

这一层的价值不是"更快"，而是**每次运行都有一个名字、一份计划、一段日志**，事后能对着它复盘。计划先行使执行前有一个冻结点：目标、命令、输入、超时都写下来，批准之后才跑；原始日志落盘，失败可重入。需要说清楚的是，dcs-harness 目前是实验性工具，依赖 DCS Cloud 与个人访问令牌（PAT），也没有公开的性能基准，所以我们只把它当作流程工具，不拿它做能力承诺。

还有一个需要警惕的边界：便利层不能成为真相的唯一存放处。如果某个结果只存在于执行层的数据库里，导出和迁移就会变成新的考古工作；所以计划、日志和产物都要落成普通文件，能被 `grep`、能被版本控制、能在没有这个工具的情况下重放。工具页在 [dcs-harness](/zh/tools/dcs-harness/)，整体思路见[实验室基础设施项目](/zh/projects/lab-infrastructure/)。

**Agent 技能，把流程写成可执行的清单。** 我们也在用 agent（智能体）做分析里重复的部分：环境检查、批量跑命令、把日志汇总成表。它确实省时间，但它改变了失败模式。

过去，一个脚本失败会报错；现在，一个 agent 可能在失败后"换个方式再试"，然后汇报成功。过去，参数在命令里；现在，参数可能来自对话上下文。过去，执行有明确边界；现在，agent 可能顺手改了不该改的文件。

所以我们对 agent 的约束和对人一样：**可以执行，不能在没有审阅的情况下改变结论**。具体做法：

- 把重复流程写成技能（skill）：一段可执行的检查清单，包含前置条件、命令、验证步骤和失败处理，而不是一段自由发挥的提示词。
- 所有命令显式写出，不用"帮我处理一下"这种委托；agent 的输出必须带原始日志和退出码。
- 关键节点设人工闸门：构图、分型、最终统计这类不可逆或影响结论的步骤，必须有人看 manifest 和中间指标。
- agent 的产物和人的产物走同一套溯源：run_id、输入哈希、环境摘要，一个都不能少。

Agent 擅长搬运、检查和归纳，不擅长替你承担责任。把这两件事分开，它才是有用的工具，而不是新的隐藏状态来源。

## 一份"无聊"的检查清单

如果你想让自己的分析更可复跑，下面这些比换工具更有效：

- 一个入口命令能从头跑到尾，不依赖交互式状态；
- 每次运行生成一份 manifest，含输入/输出哈希、环境摘要、命令、参数；
- 环境按 digest 固定，而不是按标签；
- 参数全部版本化并校验，包括种子和线程数；
- 失败运行同样归档，并在笔记里写清失败原因；
- 产物按内容寻址，旧版本只标记废弃，不删除；
- 文档里写"怎么判断这次运行是成功的"，而不只是"怎么运行"。

这些做法没有一项需要新框架，也没有一项能带来演示效果。但它们让分析从"某个人的手艺"变成"实验室的资产"。可复现性的代价是无聊，回报是：当有人问"这个数是怎么来的"，你不需要回忆，只需要打开一个文件。

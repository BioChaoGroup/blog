模式生物的泛基因组（pangenome）有现成的参考、现成的注释、现成的样本清单。非模式生物什么都没有：参考基因组可能只是一个草图，样本之间的分化程度未知，注释来自一个近缘物种的自动迁移。在这种条件下构图，最容易犯的错误是把"图建出来了"当成目标。

图只是索引。它把多个个体的序列差异编码成节点和路径，让下游能问"这个样本在这段区域是什么结构"，但它不会替你判断哪个组装是错的、哪个样本被污染了、哪个重复区已经塌缩。这篇笔记按我们实际做项目的顺序走一遍：先决定要哪种图，再做组装 QC，然后构图、迁移注释、把变异分型回样本，最后列出最常见的坑。

## 先决定你要哪种图

泛基因组图至少有两类，目的不同，不能混着用。

**以结构变异为主的参考图。** 代表工具是 minigraph（以及 minigraph-cactus）。它把组装之间较大的差异（插入、缺失、倒位等）表示为图的边，输出 rGFA 格式，节点带有相对参考的 rank。它的优点是构建快、支持增量添加样本、能保留线性参考坐标，适合"把新样本分型回参考"这种任务。

**全比对图。** 代表流程是 pggb（whole-genome alignment 之后用 seqwish 建图、smoothxg 平滑）。它试图把包括 SNP 在内的所有变异都编码进图，图更密、分辨率更高，但计算量与调参成本也高得多，适合样本数不太大、需要精细比较的场景。

选择依据不是"哪个更先进"，而是三个问题：样本之间有多近？你要回答的是结构变异还是单碱基差异？下游分析能不能消费图格式？如果只是想给一个非模式物种做 SV 分型，minigraph 风格的图通常已经够用；如果目标是研究基因存在/缺失与局部适应，才值得上全比对图。

## 构图之前：组装 QC 是第一道门

图的上限由输入组装决定。一个污染样本或一个塌缩的重复区进入图之后，会被所有下游分析继承，而且很难在图上事后修正。我们至少检查五件事：

- **连续性。** contig N50、最长 contig、总长与预期基因组大小的偏差。非模式生物常没有可靠的基因组大小估计，可以用 k-mer 谱做一个独立估计。
- **完整性。** BUSCO 或同类单拷贝直系同源基因的完整度。注意选对 lineage 数据集；选错 lineage 会让完整度看起来毫无意义。
- **污染。** 组装里混入细菌、真菌或共生体序列是常态。用比对或 k-mer 分类筛一遍，尤其是从环境样本分离培养的物种。
- **单倍型结构。** 杂合度高的个体，组装可能把两条单倍型分开，也可能塌缩成一条。分型组装（phased assembly）比"塌缩后再猜"可靠得多。
- **重复区。** 组装长度明显小于 k-mer 估计，通常意味着重复塌缩。图对这种错误极其敏感：塌缩后的单拷贝节点会让所有样本看起来都一样。

```bash
# 最小组装体检：连续性、基因组大小交叉验证、完整度。
seqkit stats -a assembly.fa
kmer_hist mer.counts 2>/dev/null | head   # 或用 jellyfish/kmc 估计基因组大小
busco -i assembly.fa -l <lineage> -m genome -c 16 -o busco_out

# 污染筛查：取一部分 contig 做分类，或比对到筛选过的参考库。
minimap2 -x asm5 contaminants.fa assembly.fa 2>/dev/null | head
```

QC 之后还要做**样本选择**。泛基因组的价值来自多样性，但一个低质量的高分化样本会把图搅乱。我们的经验是：宁可少一个样本，也不要让一个可疑组装进入图；如果必须保留，就在图里给它独立的路径名，并在下游分型时标记出来。

## 构图：minigraph 与 pggb 的最小命令

minigraph 的典型用法是以一个参考为骨架，逐个加入组装：

```bash
# 1) 以参考为骨架，加入其余组装；-xggs 是组装图预设。
minigraph -cxggs -t 16 reference.fa sample1.fa sample2.fa > graph.gfa

# 2) 图的基本统计：节点数、边数、路径数、总长。
gfatools stat -l graph.gfa

# 3) 后续新增样本时，把已有图当作参考增量添加。
minigraph -cxggs -t 16 graph.gfa sample3.fa > graph.v2.gfa
```

pggb 则从一组组装直接构建：

```bash
# -s 片段长度、-p 最小比对一致性、-n 每个序列的最大映射数、-t 线程。
pggb -i assemblies.fa -o pggb_out -t 16 -s 5000 -p 90 -n 5 -k 19

# 产物里的 *.smooth.final.gfa 是可用的图；odgi 用来统计与检查。
odgi stats -i pggb_out/*.smooth.final.og -S
```

两个参数最影响图的可读性：`-s` 控制节点被切得多碎，`-p` 控制多相似的序列才被允许连在一起。`-p` 放得太松，近缘但不同的重复区会被错误地合并；收得太紧，真实的等位序列又会被切成互不相连的碎片。没有一组参数对所有物种都好，必须看图、看下游分型结果再回头调。

## 注释迁移：把基因放到图上

非模式生物的注释本来就不可靠，迁到图上会再损失一层。可行的做法是分两步：

1. **先把注释迁移到每个组装。** 有近缘物种的蛋白序列时，用蛋白比对（如 miniprot）比直接搬 GFF 更稳；也可以先用 Liftoff 之类工具做线性基因组之间的坐标迁移，再用蛋白证据校正。
2. **再把坐标落到图上。** 图上的位置由"节点 + 节点内偏移"表示。用 `odgi position` 或图工具自带的注释映射，把每个 CDS 的起止坐标转成节点区间。

迁移动手之前先想清楚要回答什么。如果下游只关心"某个基因在不在"，做基因存在/缺失矩阵就够了；如果关心"基因结构是否完整"，就必须检查起始/终止密码子、移码和内含子边界。自动迁移最常见的错误是**把旁系同源基因（paralog）错配到直系同源位置**，尤其在多拷贝基因家族和重复区。用双向最佳比对、检查覆盖度与 identity，比盲信单向结果可靠。

## 把变异分型回样本

图建好之后，最有用的操作是把新样本的读段比对到图上，再把比对结果转成变异。以 vg 工具链为例：

```bash
# 1) 读段比对到图。giraffe 需要 .gbz / .min / .dist 三种索引。
vg giraffe -Z graph.gbz -m graph.min -d graph.dist \
           -f sample.fq.gz -t 16 > sample.gam

# 2) 把比对打包成覆盖度，再调用变异。
vg pack -x graph.gbz -g sample.gam -o sample.pack
vg call graph.gbz -k sample.pack -s sample > sample.vcf

# 3) 需要线性坐标时，把图上的结果投影回参考。
vg surject -x graph.gbz sample.gam > sample.surjected.gam
```

非模式生物的分型有三个额外难点。第一，**重复区的多比对（multi-mapping）**会让覆盖度被摊薄，看起来像缺失；第二，**图的密度**会影响 call 的灵敏度，节点太碎时一个真实变异可能被拆成几个；第三，**没有真值集**，你无法用"已知变异召回率"来调参。我们的做法是用留一法（leave-one-out）：把一个已测序样本从图中去掉，构图后再用它做分型，检查已知的变异能不能被找回。这不能替代真值，但能暴露流程的系统性问题。

## 最常见的坑

按我们踩过的频率排序：

1. **图纠缠（entanglement）。** 高度相似但结构不同的区域互相连接，图变成一团毛球，比对器在里面迷路。检查节点度数分布和泡状结构（bubble）数量；缓解手段包括收紧 `-p`、提高 `-s`、用 `gfaffix` 去掉冗余节点、以及按染色体分段构图。
2. **重复塌缩。** 组装阶段合并了重复拷贝，图上只剩一个节点，所有样本都被分型成"相同"。这类错误不会报错，只会让生物学结论安静地错掉。
3. **样本 QC 缺失。** 一个污染或低完整度的组装进入图，会拉低整个图的可用性；图的构建过程不会替你发现它。
4. **参考偏倚。** 以某个参考为骨架时，其他样本的变异表示方式受参考影响；rGFA 的 rank 和路径命名要保留好，否则下游无法区分"参考"与"样本"。
5. **把图当终点。** 图是索引，不是结论。建完图之后仍然要做分型、关联或比较分析，否则只是换了一种格式存序列。

最后一句实话：非模式生物的泛基因组，大部分工作量在构图之前和之后，而不是构图本身。组装 QC 和分型验证做扎实，minigraph 级别的图就能支撑很多问题；反过来，图再漂亮也救不了错误的输入。项目背景见 [泛基因组项目页](/zh/projects/pangenome-w-anomalus/)，基础设施层面的可复跑问题见[分析基础设施项目](/zh/projects/lab-infrastructure/)。
